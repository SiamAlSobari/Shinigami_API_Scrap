## Findings

1. **HIGH - R-39** - Inline error panel adds a second `<h1>` on pages that keep their masthead.
   - `ServerError.tsx:106` always renders `<h1>`.
   - Pages with their own `<h1>`: `_main.home.tsx:149`, `_main.update.index.tsx:215`, `_main.search.index.tsx:123`, `_main.genre.index.tsx:91`, `read.$comicId.$chapterId.index.tsx:434`.
   - Reason: a document must have one `<h1>` and no broken heading outline.
   - Fix direction: heading-level prop (`h2` inline, `h1` full page), or render the panel title as `<h2>` and keep one page `<h1>`.

2. **HIGH - R-38** - Unknown and non-500 statuses are displayed as `HTTP 500`.
   - `ServerError.tsx:57-62` returns `code: "500"` for every status not handled above it.
   - A 400, 401, 403, or a network error with no status will claim a 500 that never happened.
   - Reason: the UI must not invent a status or an error class.
   - Fix direction: use the real status when known; use a neutral label such as `GALAT` or `JARINGAN` when unknown, with matching copy.

3. **HIGH - R-39** - Error panel buttons do not show the required pointer affordance.
   - CDP computed style: retry button `cursor: default`; disabled retry button `cursor: default`.
   - No base-layer rule in `src/styles.css` sets `cursor: pointer` for enabled controls or `cursor: not-allowed` for disabled controls.
   - Reason: every enabled control must look usable; every disabled control must look disabled.
   - Fix direction: add the two base rules once in `styles.css`, or add the classes to the panel controls.

4. **MEDIUM - R-38** - Panel header always says `SERVER ERROR`, including for 404 and 429.
   - `ServerError.tsx:96` is static.
   - The code shown at `ServerError.tsx:95` can be 404 or 429, which are not server errors.
   - Reason: the label contradicts the status printed next to it.
   - Fix direction: derive the label from the status class (`TIDAK DITEMUKAN`, `BATAS PERMINTAAN`, `GALAT SERVER`).

5. **HIGH - R-27** - `/update` and `/home` still have no empty state.
   - `_main.update.index.tsx:295-300` maps `comics?.data` with no zero-length branch.
   - `_main.home.tsx:200-206`, `236-242`, `266-272` map data with no zero-length branch.
   - Reason: every data view needs empty, loading, and error states; the error state now exists, the empty state does not.
   - Fix direction: add an explicit empty panel per section, or one shared empty state.

6. **HIGH - R-39** - The error document keeps the generic site `<title>`.
   - The invalid series response still serves `KOMIK READER : Baca KOMIK Online Terbaru & Populer`.
   - Reason: a whole HTML document needs a title that identifies the current view.
   - Fix direction: set an error title in the error boundary head, for example `Gagal Memuat Halaman - KOMIK READER`.

7. **LOW - R-31** - No one-line rationale is recorded for the new error UI decisions.
   - The site has a direction contract in `_main.index.tsx`, but the panel itself has no written reason for the inline panel, the rose accent, or the instrument-style header.
   - Reason: every major visual decision must have a one-line reason.
   - Fix direction: add three lines to `DESIGN.md` or a component comment.

## Not findings

- R-03: 390px layout has no horizontal overflow and 44px tap targets.
- R-25: the panel reuses existing site tokens; no new low-contrast pair was introduced.
- R-26: both links have real destinations and were clicked successfully.
- R-32: `styles.css:26` defines a visible `:focus-visible` outline.
- R-29: the panel uses the existing neutral palette plus the single rose accent.
- R-02: no em dash in the new copy.
